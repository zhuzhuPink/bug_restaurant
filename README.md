# Bug 小餐馆 · Windows 3D 桌面版

## 直接启动（推荐目录版或安装版）

- **便携单文件**：双击 `D:\bug_restaurant\app\release\1.2.7\BugBistro-1.2.7-Windows-x64.exe`。每次启动都需先解压到临时目录，无需安装 Node.js、运行命令或启动网页服务。
- **目录版（启动更快）**：双击 `D:\bug_restaurant\app\release\1.2.7\win-unpacked\Bug小餐馆.exe`。移动时请保留整个 `win-unpacked` 文件夹。
- **安装版**：双击 `D:\bug_restaurant\app\release\1.2.7\BugBistro-1.2.7-Setup-x64.exe` 安装，之后使用桌面快捷方式，避免便携包每次自解压。
- 源码目录的 `启动小餐馆.cmd` 会读取当前版本并启动对应目录版，不再指向旧版 `release\win-unpacked`。
- 默认入口是当前的 **3D 餐馆街区**，不是旧的二维餐馆。默认“斜摆视角”，保留立面与俯角，可以手动切换摆正；旧的默认视角配置会一次性迁移，之后尊重手动选择。
- 普通窗口及设置界面仍按 **16:9 电脑**设计；桌面背景和全屏按实际比例扩展周围街区，餐馆不拉伸。
- 尚未进行数字签名，Windows 可能提示未知发布者。请确认文件来源，不要关闭系统安全防护。

## 默认桌面背景与托盘设置

1. **双击 EXE 后直接成为动态桌面背景**，不弹设置窗口，不需要 CMD。程序常驻系统托盘。
2. **右键托盘图标 →「打开界面」**（或双击图标），打开独立的正常设置窗口；背景仍在桌面运行，不会被搬回窗口。
3. 设置即时保存并应用；点右上角关闭或「收起到托盘」只隐藏设置窗口。选择「退出小餐馆」才停止背景并退出。
4. 设置里的 **「开机自启动」** 控制 Windows 登录启动项；开启后每次登录直接成为桌面背景，不弹设置。默认不替用户开启。开发模式禁用此项。
5. 便携版启动项指向原始 EXE，不指向临时解压目录。启用后请保持 EXE 的路径不变；移动前先关闭自启动，移动后重新开启。目录版也需保留完整文件夹。
6. 程序挂到 Explorer 的 `WorkerW / Progman` 桌面宿主，位于桌面图标后面，不是普通置底窗口或截图壁纸。
7. 在**桌面空白处**单击备料区、烹饪区、出餐区、餐桌或 Bug 气泡可查看明细，明细支持关闭和滚动。桌面图标、图标文字、拖动、框选、右键、任务栏及普通应用不被拦截。
8. 「桌面空白处单击交互」可以单独关闭，关闭后仍播放背景。辅助进程随退出/恢复停止，主进程意外退出时也自动结束。
9. 故障排查可从设置、托盘的「恢复普通窗口（故障排查）」或 **Ctrl+Shift+B** 恢复。挂载失败会重试，最终失败才显示普通窗口并提示，**不使用置底窗口冒充成功**。

输入辅助使用 Windows PowerShell 编译内置 C#，无 CMD 窗口、无需用户输入命令。受组织策略禁用 PowerShell、无障碍接口或鼠标钩子时，桌面模式可能失败；请恢复普通窗口使用。系统安全软件/Explorer 版本、多显示器和不同缩放环境仍需分别验证。`BISTRO_DISABLE_DESKTOP_HOST=1` 可测试失败恢复；`BISTRO_START_NORMAL=1` 仅供开发验收临时跳过默认桌面启动。

## 场景与配置

- 最左侧房屋整体后退，墙体、窗台及屋檐均不再占用人行道。
- 四张桌子、随机就座方向、椅侧进出、门口进出、人物避让、厨师与服务员、三区点击均保留。
- 候位上限 **0～6 人**；两条道路共用车辆上限 **0～10 辆**，红绿灯控制通行。
- 候位、车辆、视角、动画、外景、统计、自动来单、桌面交互开关自动保存到用户数据目录的 `scene.json`；重启仍有效。
- 最小化/最大化/退出位于窗口右上角；顶部窄条可拖动窗口；桌面模式通过托盘退出。

## 数据边界

**当前这版 3D 场景仍使用本地 Mock 模拟，正式打包不意味着已经接入真实项目。**模拟新 Bug、自动来单与重置不会更改外部系统。本轮没有改变此前约定的业务状态与动画展示解耦规则。

保留旧版 Vue 数据看板及原有只读 HTTP 接入能力：托盘菜单 **“数据看板（旧版 HTTP 兼容）”** 打开，**“返回 3D 桌面场景”** 返回。两者暂未共享业务状态，不要把旧看板的 HTTP 数据误认为已经映射到 3D 场景。原 HTTP 安全限制、令牌加密、只读请求仍有效，接入说明见 `D:\bug_restaurant\app\HTTP接入说明.md`。

## 开发与验收

源码位于 `D:\bug_restaurant\app`，Git 仓库也在此处，外层 `D:\bug_restaurant` 不是仓库。

```powershell
Set-Location -LiteralPath 'D:\bug_restaurant\app'
npm.cmd ci
npm.cmd test
npm.cmd run build
npm.cmd run desktop
npm.cmd run pack
```

- `prototypes/overlook`：3D 场景实现，正式版复用同一套代码，不复制出第二套玩法。
- `scripts/build-bistro.cjs`：构建离线 3D 资源到 `dist/bistro`；Three.js 来自根目录锁定依赖，不依赖 CDN、嵌套 Demo 安装或开发服务器。
- `electron`：窗口、托盘、安全桥接、桌面宿主及可关闭的输入转发模块。
- `scripts/desktop-3d-check.cjs`：隔离用户目录，验证正式入口、16:9、场景点击、设置、桌面挂载/恢复；`BISTRO_UI=1` 会额外等待人工真实桌面点击。
- `scripts/portable-3d-check.cjs`：便携 EXE 离线默认桌面启动、独立设置、原始 EXE 启动路径及桌面往返回归。
- `scripts/startup-tray-check.cjs`：默认桌面启动、独立设置实时同步、多窗口保存、关闭设置继续运行及自启动状态；真实启动项写入验收需显式设置 `BISTRO_TEST_LOGIN=1`，使用临时验收键并在结束后清理。
- 旧的 `scripts/smoke.cjs` 和 `scripts/portable-smoke.cjs` 对应旧二维入口，不是当前 3D 入口的验收脚本。
- 验收产物位于 `prototypes/overlook/qa`（忽略目录），程序产物位于 `release`（忽略目录）。

本机通过构建、68 项单元测试、场景几何和人物/信号回归，以及真实 Explorer 宿主挂载和恢复、默认背景启动、独立设置关闭后继续运行、Windows 临时启动项开关读写及便携原始 EXE 路径回归。启动项验收已清理测试键，没有替用户开启自启动。**系统桌面物理鼠标点击与图标拖动的完整人工验收尚未完成**；自动化页面点击与原生输入模块启动测试不代替此项。Windows 10、ARM64、其他机器也未实测。

## 2026-10-27 S3 手动更新（v1.2.5）

- 设置页“版本与更新”及托盘“检查更新”读取 S3 目录 `private/bug_restaurant/latest.json`，使用 `versionCode`、`versionName`、`sha256`、`notes` 四字段协议。只有主动检查时联网，不阻塞启动。
- 发现新版后手动下载，流式校验 SHA-256；安装前再次校验，并确认退出当前程序后启动安装版。不会自动安装，不在客户端保存 S3 密钥。
- `npm.cmd run pack` 自动生成对应安装包的 `latest.json`；发布方法和权限说明见 `docs/更新发布.md`。首次需手动安装 v1.2.5，旧版没有更新入口。
- 目前实测更新源返回 403，必须由管理员允许读取更新对象后才能完成线上检查。HTTP 清单与安装包可能同时被篡改，SHA-256 不提供发布者身份认证；建议使用 HTTPS，客户端不会关闭证书校验。
- `BISTRO_DISABLE_UPDATES=1` 可关闭整个更新功能；断网、403、404、无效版本、下载超时、校验失败均明确提示且不影响餐馆运行。
