# 餐馆全屏视角选型 Demo

独立视觉原型，仅验证 16:9 电脑的构图、立体卡通表现和自动 Bug 流程；不修改旧应用。

## 立即体验

双击本目录 `启动斜俯视Demo.cmd`，启动后默认显示**摆正视角**。

- **摆正视角**：相机从餐馆正前上方看下去，墙面和地板主边线对齐屏幕横竖方向，仍能看见人物正面和家具立面。不是 90° 顶视图。
- **斜摆视角**：保留原有斜向俯视的空间感。
- 底部开关或键盘左右箭头切换；URL 的 `?variant=front` / `?variant=angled` 可复现选型。
- 右上角**桌面预览**隐藏演示 UI；Esc 或右上角退出。**全屏看店**切换全屏显示。
- 设置里可独立隐藏室外道路、邻楼和绿化，比较有无外围填充的效果。

参考《胡闹厨房》的圆润卡通、斜俯视和柔和阴影，不复用其商业资产或手动烹饪、倒计时、闯关及经济系统。人物、家具与街区均由本地程序化几何体构成。

## 顾客、气泡与车流（2026-10-26）

- 四桌每桌一位顾客，不拼桌；从现有两侧座位随机选座，入座后面朝桌心。顾客从室外经门入店，走到椅子侧边再横向入座；吃完起身从椅侧走出，再从门离开，走出画面后回收。椅背设有静态阻挡，避让或局部绕行也不能从椅背穿过去。
- 新 Bug 只触发来客表现，进店、候位及等餐不绑定具体 Bug。上菜时才临时关联本餐，任意先完成的 Bug 都可送给已落座等餐的顾客，不会被早到但未完成的 Bug 锁桌。
- 绿色服务员取菜、端菜和放菜时，以及顾客用餐时，头顶显示本餐 Bug 名称。气泡缩为 136×30 的单行名称提示，隐藏重复的状态/编号行，长名称省略；悬停查看完整名称，点击查看该条完整明细，桌面预览也保留气泡。
- 横、竖两条道路均有双向卡通车流，共用同一个车辆总额度，默认两辆分别安排到两条路。车辆保持同车道安全间距，交叉口按红绿灯分时放行，红灯和黄灯禁止新车越过停车线；只是装饰，不参与 Bug 流程。车辆和顾客资源复用，不按历史来单数量持续累积人物。

### 路口与街边细节

- 四处斑马线均横跨各自道路：白条沿车辆行驶方向延伸，沿道路横向并排铺满路宽；横路和竖路的白条方向相差 90°。道路中心虚线在路口及斑马线前断开，人行道不覆盖车行道。
- 信号依次为横路绿灯 8 秒、黄灯 2 秒、全红清空至少 1 秒，竖路绿灯 8 秒、黄灯 2 秒、全红清空至少 1 秒，行人绿灯 6 秒、全红清空至少 1 秒。已越线车辆继续驶出；行人放行时两路车辆均为红灯。
- 顾客离店沿北侧斑马线过竖向道路，红灯在路沿等待，绿灯过街；已经进入斑马线的行人可继续走完。路口仍有人或车辆时延长清空相位，不强行切换放行。
- 门垫、坡道与门框中心一致，单扇门按门洞尺寸重做，向店内打开；室外两张长椅背靠餐馆、面向道路。

### 数量设置

打开现有设置面板即可即时调整：

| 配置 | 范围 | 默认 | 设为 0 |
| --- | --- | --- | --- |
| 候位顾客上限 | 0～6 人 | 3 人 | 不展示候位，空桌仍可接待来客 |
| 两条路车辆总上限 | 0～10 辆 | 2 辆 | 停止补充车流 |

**10 辆是车辆可设置上限，不是默认值。** 调低配置后已有顾客正常就座、用餐或离场，已有车辆驶出画面再退出循环，不在画面内强行删除；自然退场期间当前数量可能暂时高于新目标。设置只在本次运行生效，重置场景保留配置，重新启动恢复默认值。

顾客总量限制为 `4 + 候位上限`，包含进出途中的顾客，最大 10 人。超限新 Bug 仍正常记录，只合并提示，不建立无限补演来客队列。有待展示餐点但缺少等餐顾客时，可在限额内补位。

### 状态统计口径

“等待备料”“正在烹饪”“本轮已完成”为互斥业务状态；“等待上菜”是已完成 Bug 中待上餐展示的子集，**不能把四张卡直接相加当成订单总数**。满桌或尚未上餐不阻塞业务完成时间。用餐及离店只推进展示，不重复改变完成状态。

暂停与倍速作用于顾客和车辆；关闭动画或隐藏室外场景时车辆冻结，恢复不会追赶积压时间。

### 人物连续行走与避让

- 由模型保存人物的真实位置；到达候位点后原地等候，状态切换不再把人放回画外。只在从门离店并走出画面后回收，调低候位配置也不会原地删除。
- 顾客、两位服务员和厨师共用人物间距约束。同向跟随、迎面或交叉时提前侧移；空间不足就停下等待，不能通过偏移渲染坐标假装避让。
- 门口采用单人通行预约，两侧设置等待点，进出人物轮流通过。移动受阻时到达时间可以延后，服务员实际到达后才交接，Bug 业务完成不等待上菜或离店。
- 常规路线受家具及椅背阻挡；拥堵时使用有范围和节点上限的局部网格绕行。不是完整人群物理，不含推挤，也不承诺任意自定义家具布局可通行。
- 避让默认开启，可通过 `new BistroModel({ avoidance: false })` 关闭人物间避让作为模型级兜底；关闭后仍精确沿通道连续移动，并保留家具阻挡和门口通行。该开发开关不新增到用户设置界面。

## 保留的场景调整

- 餐馆地台继续从 17.1×12.5 扩到 19.1×14.5，比上一版再增加约 30% 面积；四张餐桌排成左侧两排，出餐台右移，台面至最近餐桌的水平净距约 2.95，留出独立上菜通道。桌椅和角色不放大，外围街区同步外移。
- 新增橙色备料服务员，与绿色上菜服务员独立工作：取料 → 搬运食材 → 灶台交接 → 空手返回；路径绕开柜台和灶台，不瞬移。食材在搬运期间仍属等待备料，交接完才进入正在烹饪；暂停、倍速及重置同时作用于两个服务员。
- 每张桌子的空椅转向餐桌，厨师的锅铲绑定到手部握持点，随抬手和翻炒动作移动。
- 两个炉头增加蓝色焰根与暖色火尖，烹饪时点燃、空闲时熄灭；暂停会冻结火焰，关闭动画时保留静态火焰。
- 备料区、烹饪区、出餐区的实体及浮动标签均可点击，分别打开等待备料、正在烹饪、等待上菜的 Bug 明细；标签支持键盘聚焦与 Enter。面板仍只显示 Mock 数据。

## 全屏构图

首版只考虑 16:9 电脑。以 1920×1080 为交付设计基准，Demo 使用 1600×900 逻辑画布，同比缩放，已检查 1920×1080、1600×900、1280×720。其他比例不适配、不验收；误用其他比例时只等比居中，不拉伸或响应式重排。

餐馆保持完整且可读，用道路、人行道、邻楼、树木和路灯填充外围，让整个世界而非餐馆地板占满屏幕。允许裁切外围装饰，不裁切关键餐桌和状态区域。

## 动态桌面背景的实现边界

本 Demo 的全屏与桌面预览**不是**系统动态壁纸，也不会改变壁纸或桌面窗口层级。

项目已有 `app/electron/desktop.ps1` 的 Windows 桌面宿主挂载实现，后续可把确认后的场景集成进原桌面容器，挂到图标后方；需另验 Win10/11 的宿主窗口层级、DPI、鼠标穿透、任务栏、Explorer 重启、恢复普通窗口及退出。失败回退普通窗口，不能把全屏预览视为挂载成功。本次不新增系统挂载操作，也不声称已验收该能力。

## 数据与玩法

由 `bistro-rebuild/model.js` 的独立 Mock 副本扩展，模型维护四桌、备料搬运和限量顾客生命周期；`layout.js` 统一模型与场景坐标、椅侧进出路线及静态阻挡，`walking.js` 独立维护人物行走、避让与门口通行，`street.js` 统一维护道路配置、车辆和人车信号，`traffic.js` 只同步车辆外观与灯色。数据与渲染分离；统计卡、餐桌、三区和 Bug 气泡可点击查看对应明细。支持新建模拟 Bug、暂停、自动来单、倍速、重置及动画开关。

Mock 自动流转仅供演示，不读写真实 Bug；正式状态由数据源提供，动画不得自动改变真实 Bug。未接云效／HTTP，不是独立分发 EXE。
