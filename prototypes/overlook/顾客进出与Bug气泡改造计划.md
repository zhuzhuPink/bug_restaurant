# 顾客进出与 Bug 气泡改造计划

日期：2026-10-26
状态：已获用户授权实施，Demo 功能与本轮自动验收已完成。
Git 基线：`4537141`（`chore: 保存餐馆演示改造前基线`），已先保存改造前 Demo；本轮实现尚未提交。
范围：仅 `prototypes/overlook` 独立 Mock Demo；首版只考虑 16:9 电脑。

## 一、按最新反馈确定的方案

### 1. 取消拼桌，每桌一位顾客，随机选择座位方向

- 保留现有四张桌子，每桌同时最多接待一位顾客，不实现双人同桌、双 Bug 共桌。
- 每次分桌时，从该桌可用的不同侧座位中随机选择一个，顾客坐下后面向桌心；不会在坐着时随机转向。
- 座位方向、顾客坐标、餐盘位置、服务员送餐终点使用同一套布局数据，避免人物背对食物、空椅摆反或送到空座。
- 随机使用可复现的序列，方便验证；不在每帧重新抽取，也不强制所有桌朝同一方向。

### 2. 门口进出，替代椅子上的出现和消失

- 在餐馆前侧连接室外人行道的位置增加可辨认的门框与入口，保留主要通路宽度，不遮挡桌子和三区点击。
- 新 Bug 触发来客表现，但进店、候位和等餐阶段不绑定具体 Bug。流程为：室外来客 → 门外候位（满桌时）→ 预留空桌和座位 → 从门进入 → 沿通道走到椅子 → 坐下等餐 → 接收任意已完成且待展示的 Bug 餐点 → 起身 → 从门离开 → 室外不可见位置移除。来客受下述人数上限约束，不要求每个 Bug 都生成一位顾客。
- 预留桌位后不能再次分配给其他顾客；顾客起身离开座位、避开就座区域后再释放桌位。
- 满桌时在门外有序候位，不重叠坐、不丢失 Bug；进出路径使用固定通道，按桌位空闲情况分配入店，不做完整人群寻路及碰撞避让系统。
- 配送开始时才选择一位已落座、正在等餐的顾客，并临时关联本餐 Bug；送餐期间锁定目标，吃完后解除关联。先到但未完成的 Bug 不占用专属桌位，后到先完成的 Bug 可以先上餐。

### 3. 上餐与用餐显示对应 Bug 名称气泡

- 绿色上菜服务员取菜、端菜移动和放菜时，头顶显示本次配送的 Bug 名称；空手返回时隐藏。
- 顾客吃饭期间，头顶显示本次餐点临时关联的 Bug 名称；用餐结束后隐藏，不显示其他桌的内容。进店和等餐时没有专属 Bug 名称。
- 气泡绑定订单 ID 查询名称，随人物位置移动，并随摆正/斜摆视角重新投影；不把所有名称拼在公共提示上。
- 按最新反馈将气泡缩为 136×30 逻辑像素，仅显示单行 Bug 名称，不展示重复状态/编号；长名称省略，悬停查看完整名称，点击查看完整明细。
- 气泡与已有区域标签避让，优先确保名称和人物可辨认，不挡住三区点击；桌面预览保留这类场景内信息，隐藏演示控制面板。

### 4. 限制顾客数量，避免候位人群持续增长

- 最多 4 位落座顾客；候位上限通过设置界面配置，范围 0～6 人，默认 3 人。顾客实体总量上限为 4 + 候位配置值（默认 7 位），包含进店、候位、落座、起身和离店途中，不能用进出动画绕过总量限制。厨师与两个服务员不计入顾客人数。
- 只有仍有顾客名额时，新 Bug 才触发来客；达到上限后正常接收 Bug，但不生成额外顾客，只合并显示轻量“新增 Bug +N”提示。
- 不为被合并的每个来单保留一条待生成人物任务，不在空位出现后逐条补演历史来客；人物规模不随 Bug 总数增长。
- 有待展示餐点但没有等餐顾客时，可在人数上限内安排补位来客，避免餐点因缺少一次来客动画而永远无法展示。
- 满桌都在吃饭时，待展示餐点排队等待桌位；业务完成状态不等待动画，不因候位、满桌或离店速度受阻。
- 按配置限制数量并清理离场顾客及气泡，优先复用人物资源；离开画面后才移除，不在椅子上突兀消失。

### 5. 外围道路增加少量行驶车辆

- 沿现有横、竖两条外围马路分别设置双向车道，两条路共用同一总额度（不是各 10 辆），默认两辆分别安排到两条道路；加入与餐馆一致的圆润低多边形卡通车辆，不占用顾客进出的人行道和门口路径。
- 车辆上限通过设置界面配置，范围 0～10 辆，默认 2 辆；10 辆是可设置的最大值，不是默认车流量。按所设上限循环复用车辆资源，驶出画面后再从画外回到路线起点，不持续生成对象，不在画面内瞬移掉头。
- 使用固定直行路线与错开的出发时机，同车道保持安全车距；路口采用单车预约占用，完全通过后才放行下一辆，其他车辆在路口外等候。以小时间步推进避免倍速或大步进穿透，不做转弯、复杂交通 AI、实时车灯或独立车辆阴影；优先控制渲染成本。
- 车辆跟随暂停与倍速；关闭场景动画时停驶，隐藏室外场景时同步隐藏并停止更新车辆。恢复时不追赶隐藏期间积压的动画时间。
- 车辆纯属街景装饰，不参与 Bug 状态、不触发额外顾客，也不遮挡餐馆内部点击。

### 6. 数量配置界面

- 在现有设置面板新增“候位顾客上限”和“行驶车辆上限”，提供滑块、当前数值和明确范围，调整时即时应用，不要求修改代码。
- 候位顾客：0～6 人，默认 3 人；0 表示不展示候位顾客，但仍可在有空桌时安排来客。
- 行驶车辆：0～10 辆，默认 2 辆；0 表示关闭车流。
- 调高时按节奏补充；调低时立即停止超额补充，已有顾客正常就座、用餐或离场，车辆驶出画面后退出循环，不在画面内强行删除。自然退场期间数量可暂时高于新目标，界面区分当前数量与目标上限。
- 数量设置不影响 Bug 记录与业务处理；原型配置只保留在本次运行内，不新增持久化依赖。

## 二、实现边界

- 顾客身份、行为阶段、桌位预留及仅在配送/用餐期间存在的餐点关联由模型维护；渲染不再靠订单数量猜测顾客是否出现。
- Bug 业务状态与上餐展示状态分开，不再把“上桌后才算完成”作为唯一口径；Bug 完成后即记录完成，上餐、吃饭、离店单独调度，不重复改变业务完成状态。原有区域明细和数量统计要明确使用业务状态还是展示状态，不能混淆。
- 保留橙色备料服务员、绿色上菜服务员的完整运输和返回路线，不让食材、餐点凭空交接。
- 暂停冻结人物和流程，倍速统一影响动作计时；重置清理旧顾客、桌位和气泡，固定随机序列可复现。
- 现有开场预热仅用于初始化热闹场景；人数上限内由新增 Bug 触发的顾客必须完整从室外走入，达到上限时只合并提示。
- 不修改正式应用、旧原型或正式设计 Word；本文件记录本次 Demo 改造约定。

## 三、实际修改范围与顺序

1. `model.js`：补充限量顾客生命周期、随机选座、桌位预留与候位；业务完成与餐点展示解耦，配送开始才临时关联已落座顾客。
2. 视需要新增小型布局模块：统一餐桌、各侧座位、门口和通道的数据，供模拟和场景共用，避免重复坐标。
3. `scene.js`：增加门与进出路线、动态顾客及走路/就座/起身表现；调整座位朝向和按座上菜位置；加入限量循环的外围车辆，视需要拆出独立街景模块。
4. `index.html`、`main.js`、`style.css`：增加候位和车辆数量设置；实现人物 Bug 气泡、随动投影与独立 Bug 明细交互，兼容现有桌号及区域筛选。
5. `check.cjs`、`README.md`：补充自动验收和演示说明，保留原有回归项。

新建业务模块和文档按项目规则加入 Git 暂存区；不提交 commit，不改动其他已有变更。

## 四、验收清单

- 四桌最多四位落座顾客；无拼桌，同桌不同时分配两个 Bug。
- 多次来客可以选择不同方向，所有落座顾客均面向餐桌，餐盘与送餐位置匹配。
- 名额允许时新增 Bug 能看到室外来客经门走入，吃完起身经门离开；人物不在椅子上瞬间生成或删除。
- 满桌候位、预留桌位和桌位释放正确，连续来单不串客、不串单。
- 连续大量来单时，候位及顾客总数遵守当前配置（默认候位 3 位、顾客总数 7 位，含进出途中），无无界人物生成队列；新增提示合并，离场资源不持续累积。调低期间按自然退场规则收敛。
- Bug A 先来但一直未完成、Bug B 后来先完成时，B 可交给任意已落座等餐顾客；A 不锁桌。全部桌位在用餐时，后续 Bug 仍正常完成，只有上餐动画等待。
- 服务员上餐气泡和顾客吃饭气泡准确显示各自 Bug 名称；移动、换视角、重置不残留旧内容。
- 长名称可读，完整名称与明细可打开；同名不同 ID 的 Bug 不混淆。
- 暂停、倍速、大步进与逐帧推进一致；随机序列可复现。
- 备料搬运、上菜返回、炉火、手铲绑定、三区点击、桌号明细、两种视角、16:9 和桌面预览继续通过回归。
- 在两种视角下截图检查门口、通道、人物和气泡，不挤占已扩大的出餐空间。
- 外围车辆沿马路双向行驶，遵守设置上限（0～10 辆，默认 2 辆）；长时间运行资源总量有界，不穿过门口和人行道，不在画内瞬移。
- 车辆暂停、倍速、动画关闭与室外隐藏行为符合约定，两种视角及桌面预览下显示正确；结合顾客上限进行运行流畅度检查，不预先承诺未经实测的帧率。

- 配置界面覆盖候位 0/3/6 人、车辆 0/2/10 辆及运行中调高、调低；验证 0 值关闭效果、自然退场、暂停和重置，无突然消失或重复创建。

## 五、已实施方案与验收结果

按上述方案实施：每桌一人、随机坐不同侧；保留门口进出；进店不绑定 Bug，上餐时才临时关联；服务员上餐和顾客吃饭时显示本餐 Bug 名称；设置面板可调候位上限 0～6 人（默认 3 人）、车辆上限 0～10 辆（默认 2 辆），超限来单合并提示。
